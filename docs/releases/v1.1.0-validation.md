# Foreman 1.1.0 validation

Acceptance date: 2026-09-05. These checks cover the shipped content, installation and selected live host behavior. They are not a statistical estimate of advisory quality across all models or prompts.

## Automated delivery and runtime checks

The local suite passes 23 tests covering YAML validation, typed references, packaged links, command discovery, non-overwriting installation, the actual OpenClaw SDK, maintenance operations, staged Git validation, persistent profiles, task history, migration and playbook checkpoints. Content validation checks 287 core Markdown files, 51 YAML files, 4,152 typed references and 959 source links with no errors.

The release CI matrix runs on macOS and Linux with Node 22 and 24. It builds the adapter and plugin resources, checks committed bundle freshness and all release versions, packs the package and installs that tarball in a clean project. The real OpenClaw 2026.6.1 SDK is the tested baseline; 10 plugin tools are registered.

## Fresh-session state acceptance

Each host ran four separate processes against one isolated workspace. Claude Code 2.1.232 used its default Opus model. Codex CLI 0.147.0 used `gpt-5.4-mini` through an existing ChatGPT login, with external connectors, web search and multi-agent features disabled.

1. Persist solo mode, Turkish and SaaS; create a confirmed task with a deliberately past deadline.
2. Mark the task blocked, preserve its note and save pivot playbook step 2 after explicit user confirmation of step 1.
3. Read the profile, blocked task and correct next skill (`swot-pest-analysis`) in a new session without changing state.
4. Complete the task, retain notes and the checkpoint, and verify that the overdue list excludes it.

All four final sessions passed for both hosts. Actual state files, revisions, status history and task filters were checked after each turn. The other founder's record remained unchanged. Claude's fresh recall used a direct read of the selected record when a compound shell command was denied; successful writes used the runtime. Some host commands needed retries, and the runtime's lock/revision checks preserved valid records.

An earlier Codex run completed state operations but was rejected during tool-log review because it read a different founder's fictional record while locating content. The router now specifies the installed resource paths and selected-founder boundary. The final Codex run passed both command-path checks and a private marker check that detects another founder's record in tool output. Its router content is from `5867060`; the final test fixture stores the marker in a valid task description.

## Limits and reproduction

These are bounded acceptance observations. Model-generated diagnostic phrasing, schedules and links can still require review; the verified source bundle does not guarantee every generated response. Founder IDs select local records, while the AI host and operating system determine actual filesystem access. The live checks exercise correct founder selection; they are not a substitute for host access controls.

Live tests are opt-in and are not part of CI. Use the help for `scripts/live-eval.mjs` and `scripts/live-state-eval.mjs`, a fresh output directory and an explicitly approved aggregate usage limit. The state runner stops on incomplete responses, uncertain usage, wrong persisted state or another founder's record access. Raw host logs and the detailed usage ledger remain outside the repository.
